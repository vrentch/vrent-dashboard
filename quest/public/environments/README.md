# 360 environments

Every file in this folder is a **360 degree panorama** that the game can wrap
around the player as a room. The three JPGs shipped here are **placeholders**,
generated by `npm run environments`. They exist so the product looks finished
out of the box. Replace them with real photography whenever you have it.

## Required format

| Requirement | Value |
| --- | --- |
| Projection | Equirectangular (also called "spherical" or "2:1") |
| Aspect ratio | Exactly **2:1** — width must be twice the height |
| Recommended size | 4096 x 2048 |
| Maximum size | **8192 x 4096.** Larger images are refused by some Quest 3 GPU drivers and cost a lot of headset memory |
| Format | **JPG** (`.jpg`). Progressive or baseline both work |
| Quality | 80-85. Above that the file grows fast with no visible gain in a headset |
| Colour | sRGB, 8 bit. No alpha, no CMYK, no 16-bit |
| File size | Aim for under 3 MB. The whole app is downloaded over conference wifi |

Anything that is not 2:1 will be stretched. A cube map, a "little planet"
image, or a normal wide-angle photo will **not** work — it has to be a full
360 x 180 sphere.

## What produces a usable file

- A 360 camera: Insta360 X3/X4, Ricoh Theta, GoPro Max. Export "equirectangular",
  not "reframed" and not a flat crop.
- A phone panorama app in "photo sphere" mode (Google Street View app), which
  writes a proper equirectangular JPG.
- A render from Blender, 3ds Max or similar: use a panoramic/equirectangular
  camera at 4096 x 2048.
- Stitching software (PTGui, Hugin) set to output equirectangular.

## Adding your own environment

1. Export the image as above and give it a short lower-case name, for example
   `lobby.jpg`.
2. Drop it in this folder (`quest/public/environments/`).
3. Add an entry to `shared/environments.ts`:

   ```ts
   {
     id: "pano-lobby",
     name: "Lobby",
     blurb: "Our reception, captured in 360.",
     kind: "panorama",
     panorama: "environments/lobby.jpg",
     tint: "#FFB020",   // scene tint: fog, card rim light and UI glow
     ambient: 1.0,      // 0-2, lift this for a dark photo
     key: 1.1,          // 0-3, the directional light on the cards
     yawOffset: 0,      // radians, rotates the photo so its best view faces the player
   }
   ```

4. Rebuild (`npm run build:pro`, or the edition you ship) and redeploy. No other
   file needs to change.

`yawOffset` is worth setting. A panorama starts with the horizontal centre of
the image directly ahead of the player; rotate it so the interesting part of the
room is what they see first.

**Enterprise edition** can skip all of this: an operator uploads a 360 image
from the in-headset settings panel and it is stored on the device. The rules
above still apply to the file they pick.

## Regenerating the placeholders

```bash
npm run environments                  # 4096 x 2048, quality 82
PANO_WIDTH=1024 npm run environments  # fast preview while art-directing
PANO_QUALITY=90 npm run environments  # larger files, marginally cleaner skies
```

The generator reads the panorama entries out of `shared/environments.ts` and
only writes files it has a scene for (`showroom.jpg`, `alpine.jpg`,
`atelier.jpg`). Your own panoramas are never touched or overwritten.

Colours come from `shared/brand.ts` and from each entry's own `tint`, so
re-skinning the product changes the placeholders too.
